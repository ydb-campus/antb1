# Update a dependency

Step-by-step details, lockstep groups and conflict handling:
[docs/recipes/dependency-update.md](../../../docs/recipes/dependency-update.md). Toolchain background:
[ADR 0002](../../../docs/adr/0002-toolchain-pixi-conda-forge.md).

## Ask a human first

`pixi.toml`, `pixi.lock`, `cmake/`, `CMakePresets.json`, `.github/` and `tools/github/` are all "Ask a human first"
paths (AGENTS.md), and `pixi add`, `pixi remove`, `pixi update`, `pixi upgrade` and `pixi lock` always prompt.
Before touching them, stop and hand off with the exact change: package, version constraint, feature and
environment, why it is needed, and the alternatives you ruled out. Continue only with explicit approval.

## Rules

- Toolchain and libraries come from conda-forge through pixi only: never `apt`, `pip`, `conda`, `brew` or `sudo`,
  never a vendored copy or a download in CMake.
- Never hand-edit `pixi.lock`. It is regenerated by pixi 0.81.0 and must start with `version: 7`.
- Pin the minor version (`"25.0.*"`) and keep lockstep groups together: libarrow, libarrow-compute and libparquet;
  the Clang 23 packages; libstdcxx-devel and libgcc-devel. conda's Arrow goes into the default feature (`default`
  and `gcc`), build and test tools into `base`, the Clang toolchain into `llvm`, lint tools into `lint`. An Arrow
  upgrade also replaces the static build's pins (`cmake/static/arrow-sources.lock`: pins only from the ASF release
  and its versions.txt, copies of two operators each) and must pass `pixi run static-arrow --check-urls` and
  `pixi run static`.
- DuckDB is a test oracle only and is never linked into `src/`. A new external library for a module also needs the
  module allow-list in `cmake/Antb1Modules.cmake` and an ADR.
- A library linked into antb1 needs a licence compatible with Apache-2.0, its notice in the package and its source in
  the sources of the static binary; a new sysroot build needs its glibc source in `cmake/static/glibc-source.lock`
  (ADR 0034, the recipe).
- `duckdb-extension-tpch` (TPC's dbgen) and `duckdb-extension-tpcds` (TPC's dsdgen) each depend on one exact
  `libduckdb` build: update them together with `libduckdb-devel` and `duckdb-cli`, never alone (ADR 0006). A new
  TPC-DS corpus also means new digests and a new ratchet baseline.
- GitHub Actions are pinned to a full commit SHA with a `# vX.Y.Z` comment and must be allowed by
  `tools/github/allowed-actions.json`; a new or bumped action is a `.github/` change for a maintainer.

## Steps (after approval)

1. Change `pixi.toml`, then run `pixi lock` (pixi 0.81.0) and `pixi install --locked` (add `-e gcc` or `-e lint`
   for the environments you changed).
2. Build and test every environment you touched: `pixi run check-full` on Linux; the macOS leg runs in CI.
3. Update the docs that name versions (AGENTS.md, docs/architecture.md, an ADR for a major upgrade such as Arrow).
4. PR title `build(deps): ...` with the lock diff summary and the verification commands.
5. A `pixi.lock` merge conflict: never merge it by hand. Rebase on `origin/main`, take main's `pixi.toml` changes,
   then regenerate the lock with `pixi lock` (it prompts) and re-run the checks.
