# 42. Apache Arrow 26

Date: 2026-11-14

## Status

Proposed

## Context

- antb1 built on conda-forge's Arrow 25.0.1 (environments `default` and `gcc`) and on a static Arrow 25.0.0 that env
  `static` builds from pinned sources ([ADR 0033](0033-standalone-static-binary.md)). Arrow 26.0.0 (2026-10-09) and
  26.0.1 (2026-11-03) fix bugs that antb1 reaches:
  - apache/arrow GH-51223: `replace_with_mask` read a sliced BOOLEAN's values without the array's offset, so a CASE,
    AND or OR over an IN subquery's mark under OFFSET answered wrong until antb1 #368 copied such an array to offset
    0 (`UnsliceBoolean`), with a test that was to fail once Arrow read the offset;
  - GH-51135: converting a Parquet BYTE_ARRAY decimal of up to 18 digits cleared every slot with two 8-byte stores,
    so a chunk's last value wrote up to 12 bytes past its buffer. antb1 asks for the smallest decimal, so any file a
    user registers could reach it, and ASan cannot see it inside conda's Arrow;
  - GH-51496 (the Grouper's SwissTable block offsets past 2^27 blocks), GH-50840 (Take's dead 2 GiB guard), and
    stricter Parquet reading (GH-51238, GH-53518, GH-50971);
  - for the static build only: Thrift 0.24.0 (CVE-2026-55969), Brotli 1.2.1, and 25.0.1's mimalloc 3.4.1 and SVE
    decoding fixes (GH-50503, GH-50605).
- The maintainer approved a proposal of 2026-11-14 (docs/recipes/dependency-update.md, step 1) that compared
  conda-forge's builds and their dependencies, read both changelogs against antb1's code, compiled every translation
  unit against 26.0.1's headers and planned the static pins and their licences.

## Decision

- **conda's Arrow:** `libarrow` (CPU builds), `libarrow-compute` and `libparquet` `"26.0.*"` for `default` and
  `gcc`. The lock holds 26.0.1 build 6 on every platform; on osx-arm64 builds 2 to 4 load Homebrew's lz4. The lock
  also moves lz4-c to 1.11.1 (orc and libnanoarrow rebuilt for it), adds simdjson and uriparser, which Arrow 26
  requires, and drops the 14 AWS packages that the split S3 library takes away.
- **The static build** pins the ASF's 26.0.1 tarball (sha512 and GPG signature checked) and the dependencies of its
  `versions.txt`: brotli 1.2.1, mimalloc 3.4.1, Thrift 0.24.0, simdjson 4.6.4 and uriparser 1.0.2 come in,
  RapidJSON goes; 13 files, each with copies of at least two operators. `patch` leaves env `static`: Arrow 26 no
  longer patches its bundled Thrift.
- **The minimum Arrow is 26** (`cmake/Antb1Dependencies.cmake`), for GH-51223 and GH-51135. `UnsliceBoolean` and its
  test went once that test failed on 26.0.1; #368's regression test and records stay.
- **Build trees rebuild on a new Arrow.** conda installs a package's headers with the package's own mtimes, older than
  the objects of a build tree made before an upgrade, so ninja kept objects built against Arrow 25 and linked a mix
  that crashed. A changed `pixi.lock` now configures again, and the Arrow version is on every compile line.
- **Arrow 26's reader changes are accepted** and pinned in the `ParquetErrors` integration tests: a schema nested
  deeper than 100 levels is an I/O error at registration (GH-51238); a column chunk of a codec that Parquet does not
  define is one when a scan reads it (GH-53518), where Arrow 25 read it as uncompressed; a logical type that does not
  fit its physical type is dropped (GH-50910), where Arrow 25 refused the file. A TIMESTAMP on a
  FIXED_LEN_BYTE_ARRAY(12) column now registers, its column unsupported (GH-50915; read in the sources, not tested,
  for want of such a file).
- **A worker thread the pool cannot start** comes back from `Submit` as an `UnknownError` since Arrow 26
  (GH-48137). That is a limit of the machine, not a bug: exec reports it as an `ExecutionError`, exit code 1
  (`SubmitStatus`), not 70.
- **Licences:** simdjson compiles in code from PyTorch (BSD-3-Clause, whose clause 2 asks for its notice in a
  binary) and from Grisu2 (MIT) that its LICENSE leaves out. `cmake/static/licenses/simdjson-NOTICES.txt` carries
  both, and the static package's notices take every `<library>-NOTICES.txt` there, labelled by the library's pin.
  uriparser is BSD-3-Clause; Arrow 26's LICENSE.txt dropped the uriparser section that vendoring needed, so its
  notice now comes from its own pin.
- **AGENTS.md's braced-list rule** now names `ReadTable` and `ReadRowGroup`: GH-50750 removed the deprecated
  overloads of `GetRecordBatchReader` that a braced `{0}` could select, but not theirs.
- **Re-checked in 26.0.1's sources and unchanged:** no decimal32 or decimal64 kernel for `replace_with_mask`,
  `min_max` or the comparisons, so antb1's views and casts stay; `sum` still wraps at int64; `replace_substring_regex`
  still matches again on the matched text alone, so its wrapper stays; the Grouper still reads a fixed-width key's
  values where every row is NULL, so `WithValues` stays; the hashing and Grouper headers are identical.

## Consequences

- **String views:** the Grouper accepts view keys (GH-50223), but only through its generic `GrouperImpl`, and Arrow
  26 still has no view kernel for `take`, `filter` or sorting. [ADR 0027](0027-string-views.md)'s reopen trigger is
  a quarter met; its Arrow probe should run again on 26 as a follow-up.
- **Performance** is to be compared, the static 26.0.1 build against the static 25.0.0 one on a quiet machine (micro
  benchmarks, ClickBench, the queries derived from TPC-H and TPC-DS), by the maintainer or with the maintainer's
  approval. What may move: the filtered scan (GH-50421 skips values inside the decoder), bitmap copies (GH-50784),
  checked arithmetic over two arrays (GH-50280), the length check in `BinaryBuilder::Append`, and mimalloc 3.4.1.
- **Every developer's build tree** rebuilds once after pulling the upgrade; CI builds from scratch.
- The next Arrow major repeats this review: the changelog against antb1's code, a compile check, the static pins, and
  the tests that pin Arrow's behaviour.
