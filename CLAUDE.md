# Claude Code notes

AGENTS.md (imported above) is the canonical guide for every agent. This file only adds what is specific to Claude
Code; if the two ever disagree, AGENTS.md wins.

## Hooks

Configured in `.claude/settings.json`, implemented in `.claude/hooks/`. They call binaries directly (never a pixi
task) and never block, except the Stop hook below.

- SessionStart prints a status line: pixi version, installed environments, `build/dev` state, the last full passing
  test run and the branch. In cloud sessions it first runs `bash scripts/agent-setup.sh --envs "default lint"`.
- PostToolUse (Edit and Write) formats the file you changed with the `lint` environment's tools and the settings of
  `pixi run fmt` (C++, CMake, Python, TOML, Markdown; no `ruff check --fix`, so an import you add first survives),
  and mirrors `.agents/skills` to `.claude/skills` after a skill edit. Files git ignores are left alone. It does not
  lint: run `pixi run lint` before you open a PR.
- Stop, only in cloud sessions or with `ANTB1_STOP_HOOK=1`: blocks once when build-relevant files changed during the
  session after the last passing full test run (an unfiltered `pixi run test`, or `pixi run check`). Run the tests,
  or say which checks you did not run and why.

## Permissions

- Pre-approved: the named tasks of the AGENTS.md command table (except `pixi run install-git-hooks`, which prompts),
  `pixi install --locked`, read-only git and gh, and `git add` and `git commit`. Never widen this to `pixi run *`
  (in personal settings too): `pixi run` executes any command, so a wildcard would bypass every other rule.
- Ask (you are prompted): dependency changes (`pixi add`, `pixi remove`, `pixi update`, `pixi upgrade`, `pixi lock`),
  `pixi run -x`, `pixi exec`, `git push`, `gh pr create`, `gh pr merge`, and editing any path listed under
  "Ask a human first" in AGENTS.md. A `pixi run` command with a single quote inside double quotes prompts too: pixi
  does not escape quotes in forwarded arguments, so such an argument can end pixi's quoting and run another command.
  Pass SQL with `-f file.sql` or `-c -` (stdin) instead.
- Denied: editing `pixi.lock`, reading `.env` files, `sudo` and other package managers (apt, brew, pip, uv, conda,
  mamba, `pixi global`), `--manifest-path`, force pushes, `git reset --hard`, `git clean` and `git commit --no-verify`.
- The rules match command text, so they are a convenience, not a security boundary; CI is the gate. A prompt for an
  "Ask a human first" path means: stop and ask the human, do not work around it.

## Skills and subagents

- Skills (`.agents/skills/<name>/SKILL.md`, shared with Codex and Copilot): `add-sql-feature`, `write-slt-test`,
  `fix-ci-failure`, `clickbench-data`, `dependency-update`. Each has a step-by-step recipe in `docs/recipes/`.
  `.claude/skills/` is a generated byte copy: edit skills only in `.agents/skills/` (`pixi run fmt` syncs the copy).
- Subagents in `.claude/agents/`: `reviewer` (read-only; run it on your diff before you open or update a PR) and
  `test-author` (writes GoogleTest cases and runs them with `pixi run test -R ...`).

## Working style

- Use plan mode before changing a public header (`src/*/include/`) or more than one module; an interface change is
  easier to review as a plan than as a diff.
- Use `pixi run test -R '<regex>'` while iterating and `pixi run check` before every PR.

## In GitHub Actions

When Claude runs from a workflow (an `@claude` mention or an automatic PR review), hooks are disabled, only an
explicit list of tools is allowed, and every "Ask a human first" path is denied (ask rules become denials without a
human to answer). Run `pixi run test` and `pixi run lint` yourself. If the change needs a protected path (workflows,
`pixi.toml`, presets, `cmake/`, AGENTS.md, gate configs, the ClickBench ratchet), stop and hand off: describe the
exact change (file and diff) in your reply so a maintainer can apply it.
